# Visual Prototype — Canonical Visual Source of Truth

> **Status**: Active. Replaces `temp/visual-prototype-gate.md`. Generated by Claude Design 2026-05-16 against the SoT after the BR-501 recast.
> **Target codebase**: SwiftUI macOS app under `TranscriptShadow/`. The visuals in this prototype are the implementation target — match the *pixels*, not the JSX structure.

---

## What this is

A self-contained React/JSX prototype that visualizes the six-screen experience defined in `SoT/SoT.USER_JOURNEYS.md`. No build step — `project/index.html` runs in any browser via CDN-loaded React 18 + Babel standalone. The design tokens in `project/src/tokens.jsx` are lifted verbatim from `SoT/SoT.DESIGN_COMPONENTS.md` DES-301..305.

## How to view it

```bash
open design/visual-prototype/project/index.html
```

Or any browser that can open `file://` URLs. No npm, no bundler, no localhost server. The page renders a design canvas with the money shot, the user-journey filmstrip, all six screens, and the token sheet.

## JSX → SwiftUI implementation map

The target codebase is SwiftUI. **Recreate the visuals, do not copy the JSX structure.** The JSX uses inline styles and `window.X = X` exports for the no-build runtime; the SwiftUI port should use real types, `EnvironmentObject` for theming, and proper file boundaries. EPIC-07 Phase C in `epics/EPIC-07-ui-implementation.md` lists the file paths below as deliverables — this README is the bridge between the visual and that plan.

## Load-bearing rules to internalize

- **BR-501** (`SoT/SoT.BUSINESS_RULES.md:311`): main window hidden during recording; HUD exposes ONLY Stop; no timer, waveform, source toggles, or settings on the recording surface. The prototype's `scr002.jsx` enforces this — copy that constraint into SwiftUI.
- **DES-105 vs DES-106 are peers**, not primary/degraded. The prototype renders both side-by-side intentionally. Visual parity is mandatory: same red dot, same 1Hz oscillation, same Stop layout.
- **RISK-008** (`PRD.md:253`): if DES-105 cannot stay above fullscreen meeting apps, promote DES-106. The prototype's `NotchMenuBar` uses an NSPanel-equivalent visual at `.statusBar + 1`; the spike to verify this lives in EPIC-07 Phase A.
- **Recording red (#EF4444)** appears ONLY on `RecordButton` and the HUD dot — nowhere else. Use `DES-305` `.error` for true errors (same hex, but semantically different role).
- **Density modes** (DES-203): SCR-001/003/005 are Spacious (≤600pt centered content); SCR-004/006 are Dense (full-width). SCR-002 is a HUD — own surface, no density mode.

## Validated against SoT

The prototype's token sheet, layout, and component inventory were generated from the prompt at `chats/chat1.md` (pasted from the SoT-walkthrough assembled during the 2026-05-16 design audit). The Claude Design session confirmed:

- DES-301 palette (bg `#0A0A0B` / sidebar `#141415` / accent `#2DD4BF` / recording `#EF4444` / 6 speaker pastels) — pixel-matched in `tokens.jsx`.
- DES-001 has no recording state (per the post-BR-501 spec) — `RecordButton` in `scr001.jsx` has no Stop variant.
- DES-002 is pre-flight only — `PreRecordLevels` only renders on SCR-001.
- DES-105 + DES-106 are peer surfaces with identical content shape — `scr002.jsx` renders them side-by-side as a deliberate comparison.

## What this is NOT

- Not a SwiftUI scaffold — it's a visual reference. No SwiftUI code lives here.
- Not source-of-truth for behavior — that lives in `SoT/SoT.USER_JOURNEYS.md` and the `epics/EPIC-07-ui-implementation.md` plan. Visual decisions in this prototype that conflict with the SoT lose to the SoT.
- Not a thing to render-then-screenshot to "see the design." Read the JSX directly — every dimension, color, and layout decision is in the source.

## How to update the prototype

When the SoT changes (new screen, recast component, new business rule that affects visuals):

1. Update `SoT/SoT.DESIGN_COMPONENTS.md` and `SoT/SoT.USER_JOURNEYS.md` first — those are the canonical specs.
2. Open a fresh Claude Design session against the updated SoT.
3. Replace `design/visual-prototype/` with the new handoff.
4. Update the JSX → SwiftUI map above.
5. Update `temp/visual-prototype-gate.md` if you're superseding it again.
